# Лабораторная работа №1. Демон «Напоминалка» (вариант 19)

Демон раз в 10 секунд проверяет события из конфигурационного файла и в нужное
время открывает новое окно терминала с текстом напоминания. События добавляются
скриптом `add_event.sh` в формате `add_event date time [flag] text`, где флаг
`-h` / `-d` / `-w` задаёт повтор каждый час / день / неделю.

## Сборка

```sh
./build.sh           # результат: ./reminder, промежуточные файлы удаляются
./build.sh --test    # + сборка и запуск всех тестов
```

Нужны `g++` (C++17), `cmake` ≥ 3.16. Флаги компиляции: `-Wall -Wextra -Werror`.

## Запуск

Демон открывает окна, поэтому запускать его нужно **от своего пользователя из
графической сессии** (не root, не из cron): переменные `DISPLAY` /
`WAYLAND_DISPLAY` наследуются от запускающего терминала.

```sh
./reminder                      # конфиг reminder.conf из текущего каталога
./reminder /path/to/my.conf     # или явно

./add_event.sh 2026-10-12 18:30 Сдать лабу по ОС
./add_event.sh 2026-10-12 09:00 -d Зарядка

kill -HUP  $(cat ${XDG_RUNTIME_DIR:-/tmp}/reminder.pid)   # перечитать конфиг
kill -TERM $(cat ${XDG_RUNTIME_DIR:-/tmp}/reminder.pid)   # завершить
journalctl -t reminder -f                                 # журнал
```

## Конфигурационный файл

```
# комментарий
terminal = xterm -e                          # необязательно
add_event 2026-10-12 18:30 -d Сдать лабу по ОС
```

- Путь к конфигу при запуске превращается в абсолютный, поэтому SIGHUP работает
  и после того, как демон перешёл в `/`.
- `terminal` — команда терминала и её флаг запуска команды. По умолчанию
  `x-terminal-emulator -e` (стандартная ссылка Debian/Ubuntu на терминал
  системы), если его нет — `xterm -e`.
- Некорректные строки пропускаются с предупреждением в журнале, остальные
  применяются.
- Разовое событие из прошлого (старше минуты) пропускается; повторяемое
  переносится на ближайшее будущее срабатывание.
- Уже показанное событие после SIGHUP повторно не показывается.

## Поведение демона

| Что | Как |
|---|---|
| Демонизация | двойной `fork`, `setsid`, `umask(0)`, `chdir("/")`, stdin/out/err → `/dev/null` |
| Защита от повторного запуска | pid-файл `$XDG_RUNTIME_DIR/reminder.pid` (иначе `/tmp`). Новый процесс проверяет pid через `/proc/<pid>/stat` (жив, не зомби, имя `reminder`), шлёт ему `SIGTERM`, ждёт завершения, после демонизации пишет свой pid |
| SIGHUP | перечитать конфиг |
| SIGTERM | сообщение в журнал, удаление pid-файла, выход |
| Журнал | `openlog` / `syslog` / `closelog`, facility `LOG_DAEMON` |
| Окно | `fork` + `execvp` терминала с `sh -c '…' sh "<текст>"`: текст передаётся аргументом, а не вклеивается в команду, поэтому кавычки и `$(…)` в нём безопасны |
| Зомби | закрытые окна убираются `waitpid(-1, WNOHANG)` каждый тик |

Класс `Daemon` — синглтон (`Daemon::instance()`, конструктор приватный,
копирование запрещено).

## Тесты

```sh
./build.sh --test                 # всё: unit + integration
```

Из каталога сборки (например, `cmake-build-debug` в CLion):

```sh
ctest -L unit                     # только unit-тесты
ctest -L integration              # только интеграционные
ctest -R sighup -V                # один набор с полным выводом
./test_event advance_             # unit-тесты, чей id содержит "advance_"
TEST_CASE="H02 H04" bash ../tests/integration/test_sighup.sh ./reminder   # отдельные кейсы
```

**Unit** (`tests/unit/`, свой мини-фреймворк `test.h` без внешних библиотек) —
классы по отдельности: разбор строк и дат (31 февраля, летнее время), конфиг,
расписание и повторный SIGHUP, pid-файл и `/proc`, запуск «терминала».
Каждый тест — `TEST(id, "что проверяет")`; при падении печатаются файл:строка,
проверка, «ожидалось / получено» и контекст (например, какая строка таблицы
входных данных упала).

**Integration** (`tests/integration/`) — запускают настоящий `reminder` как
чёрный ящик. Кейсы пронумерованы по наборам:

| Набор | Кейсы | Что проверяет |
|---|---|---|
| `test_daemon` | D01–D06 | фон, pid-файл; по `/proc`: нет терминала, своя сессия, не лидер сессии, cwd `/`, fd → `/dev/null`, umask; SIGTERM / SIGINT; ошибки запуска |
| `test_events` | E01–E07 | показ в нужный момент и ровно один раз; будущие / прошлые / повторяемые; плохие строки; спецсимволы не исполняются |
| `test_sighup` | H01–H05 | `add_event.sh` и `kill -HUP`; показанное не повторяется; относительный путь после `chdir("/")`; удалённый конфиг |
| `test_restart` | R01–R05 | второй запуск гасит первый; чужой / мёртвый / мусорный pid в файле; «зависший» старый экземпляр |
| `test_add_event` | A01–A07 | запись строк, все ошибки ввода, конфиг без `\n` в конце, демон не запущен, чужой pid |

Изоляция: у каждого кейса свой каталог и свой `XDG_RUNTIME_DIR`, поэтому тесты
не трогают работающий демон пользователя. Вместо терминала — заглушка, которая
записывает текст напоминания в файл.

Проверки записей в системном журнале (сообщения о запуске, SIGHUP, SIGTERM,
предупреждения о плохих строках) выполняются, если тест может читать журнал:
пробная запись через `logger` должна найтись в `journalctl`. Иначе они
помечаются как пропущенные (SKIP) с причиной — обычно нужна группа `adm`
или `systemd-journal`.

**Логи** — в `test-logs/` (в `.gitignore`):

```
test-logs/
├── test_event.log ...        отчёт каждого unit-набора
├── test_sighup.log ...       шаги, команды, их stdout/stderr/код, с временными метками
└── test_sighup/H02/          артефакты упавшего кейса: конфиг, показанные
                              напоминания, вызовы терминала, процессы, журнал демона
```

## Ограничения

- Время в конфиге — с точностью до минуты, проверка раз в 10 с: напоминание
  приходит с задержкой до 10 секунд.
- Память о показанных событиях хранится в процессе: если перезапустить демон в
  ту же минуту, когда сработало событие, оно покажется ещё раз.
